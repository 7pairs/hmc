# 半荘成績の仕様・設計・テスト項目

## 仕様

初回の実戦試用に向けて、卓で供託を精算し、4人で確認した素点から1半荘分の着順と成績ポイントを求める。入力画面、保存、リーグ順位への反映、アプリでの供託の精算は別の作業で扱う。（参照：[手順書0003](../procedures/0003-calculate-match-results.md)）

### 入力と結果

- 素点は4人分を点単位の整数で受け取る。各人の素点は100点刻みとし、負の値も受け付ける。精算済みの素点の合計は100,000点とする。
- 順位点は1位から4位までを整数ptで受け取る。Mリーグ方式では順に `+50 / +10 / −10 / −30 pt` を渡す。
- 成功時は4人分の結果を素点の入力順に返す。各人の結果は着順と成績ポイントを含む。

### 着順と成績ポイント

着順は素点の高い順に付ける。2人が同点なら、2人に同じ着順を付け、2人が占める順位の順位点を平均してそれぞれに配分する。次の着順は同着の人数ぶん進む。同点トップなら着順は上から `1 / 1 / 3 / 4` で、Mリーグ方式では同着の2人にそれぞれ `+30 pt` の順位点を配分する。同点が2組あるときも組ごとに同じ計算を行う。（参照：[Mリーグ公式戦ルール 第６章第２条](https://m-league.jp/about/)）

成績ポイントは `(素点 − 30,000点) ÷ 1,000` に配分後の順位点を足した値とする。結果は0.1 pt単位で表し、計算途中の丸めは行わない。

### 入力エラーと対象外の半荘

次の順で条件を確認し、最初に該当した理由を返す。この場合は4人分の成績を返さない。

1. 100点刻みでない素点がある。
2. 4人の素点の合計が100,000点と一致しない。
3. 3人以上の素点が同じである。

3人同点は現在のリーグで発生例がなく、初回試用では4人全員の同点も含めて3人以上の同着を対象外とする。精算後の素点に差があると、元の同着を素点だけでは判別できない場合がある。

試用中は最終局の点棒のやり取りを終えた時点で同着を確認する。卓に供託が残っている場合は、配る前の素点を使う。3人以上が同着なら、その半荘は紙に記録する。

流局で半荘が終わり、2人が同点トップで供託が残っている場合は、供託1本につき500点ずつ2人に配る。2人は精算後も同点になる。精算後の4人分の素点を入力すると、成績の計算では2人を同着として扱い、1位と2位の順位点を平均して配分する。（参照：[Mリーグ公式戦ルール 第６章第２条第５・６項](https://m-league.jp/about/)）

将来の対応では、供託の精算で素点に差が付いたあとも同着だったことを記録できるようにする方法と、順位点の按分で出る端数を起家からの席順に従って配る方法を検討する。供託をアプリで精算する場合は、精算前の素点と残った供託を受け取り、供託込みの合計を確認してから配分する案を検討する。（参照：[Mリーグ公式戦ルール 第６章第２条第５・６項](https://m-league.jp/about/)）

## 設計

計算は `shared/src/commonMain/kotlin` に置き、AndroidとiOSで共有する。計算関数 `calculateMatchResults` は `RawScores` と `PlacementPoints` を受け取る。どちらも4つの `Int` を持つデータクラスとし、`RawScores` の順番は呼び出し元が指定した選手順、`PlacementPoints` の順番は1位から4位までとする。

戻り値には `sealed interface MatchResult` を使う。`Success` は着順 `place: Int` と0.1 pt単位の `pointsInTenths: Long` を持つ `PlayerResult` を入力順に4件保持する。`Failure` は理由を表す `MatchFailureReason` を1つ保持する。入力の不備と対象外の半荘は `Failure` で呼び出し元に伝える。

| `MatchFailureReason` の値 | 返す条件 |
| --- | --- |
| `INVALID_SCORE_INCREMENT` | 100点刻みでない素点がある |
| `INVALID_SCORE_TOTAL` | 素点の合計が100,000点と一致しない |
| `UNSUPPORTED_TIE` | 3人以上の素点が同じ |

固定する100,000点と30,000点にはそれぞれ名前を付け、前者は精算済みの素点の検証に、後者は成績ポイントの換算に使う。入力時の選手の位置を保持したまま素点の降順に並べ、同じ素点ごとに着順の決定と順位点の配分を行う。成績ポイントを計算したら入力順に戻す。

素点と順位点は演算前に `Long` に変換する。素点の合計、返し点との差、順位点の換算と按分を `Long` で行うことで、`Int` の範囲を超える途中結果も扱える。0.1 pt単位で計算するには、素点と返し点の差を100で割り、配分後の順位点を同じ単位で加える。単独順位の順位点は整数ptを10倍し、2人同着では該当する順位点の和を5倍する。順位点の和が奇数でも、0.5 ptの端数を保てる。

## テスト項目

自動テストは `shared/src/commonTest/kotlin` に置き、`commonTest` に `implementation(kotlin("test"))` を追加する。手順2で `shared` の `android` ブロックに `withHostTest {}` を追加し、ローカルのJVMで `./gradlew :shared:testAndroidHostTest` を実行する。実装前にテストが実際に走り、期待値との不一致で失敗したことを記録する。実装後は同じタスクで全項目の成功を確認する。（参照：[Android Gradleライブラリプラグインのテスト設定](https://developer.android.com/kotlin/multiplatform/plugin#configure-tests)・[Kotlin Multiplatformの共通テスト](https://kotlinlang.org/docs/multiplatform/multiplatform-run-tests.html)・[Androidホストテストのタスクの使用例](https://github.com/JetBrains/compose-multiplatform/blob/master/components/resources/library/build.gradle.kts)）

表の素点は各条件を確かめるための例で、結果は入力順に記す。成績ポイントは表ではptで示し、テストでは0.1 pt単位の値と比較する。順位点は表で指定したケースにはその値を使い、ほかのケースにはMリーグ方式の値を使う。

| ケース | 素点（点） | 期待する着順 | 期待する成績ポイント（pt） |
| --- | --- | --- | --- |
| 同着なし、負の素点あり | `20,100 / 50,000 / −1,100 / 31,000` | `3 / 1 / 4 / 2` | `−19.9 / +70 / −61.1 / +11` |
| 同点トップ | `35,000 / 20,000 / 35,000 / 10,000` | `1 / 3 / 1 / 4` | `+35 / −20 / +35 / −50` |
| 同点2位 | `40,000 / 25,000 / 25,000 / 10,000` | `1 / 2 / 2 / 4` | `+60 / −5 / −5 / −50` |
| 同点が2組 | `35,000 / 15,000 / 35,000 / 15,000` | `1 / 3 / 1 / 3` | `+35 / −35 / +35 / −35` |
| 異なる順位点での同点トップ。順位点は `+51 / +10 / −11 / −30 pt` | `35,000 / 20,000 / 35,000 / 10,000` | `1 / 3 / 1 / 4` | `+35.5 / −21 / +35.5 / −50` |
| 順位点の和が `Int` の範囲を超える同点トップ。順位点は `+2,147,483,647 / +2,147,483,646 / −2,147,483,647 / −2,147,483,646 pt` | `35,000 / 20,000 / 35,000 / 10,000` | `1 / 3 / 1 / 4` | `+2,147,483,651.5 / −2,147,483,657 / +2,147,483,651.5 / −2,147,483,666` |

| ケース | 素点（点） | 期待する失敗理由 |
| --- | --- | --- |
| 合計は100,000点だが100点刻みでない | `50,050 / 30,950 / 20,000 / −1,000` | `INVALID_SCORE_INCREMENT` |
| 100点刻みだが合計が100,000点に満たない | `50,000 / 30,000 / 20,000 / −1,000` | `INVALID_SCORE_TOTAL` |
| 3人同点 | `30,000 / 30,000 / 30,000 / 10,000` | `UNSUPPORTED_TIE` |
| 4人同点 | `25,000 / 25,000 / 25,000 / 25,000` | `UNSUPPORTED_TIE` |
| 刻みと合計の両方が条件を満たさない | `50,050 / 30,000 / 20,000 / −1,000` | `INVALID_SCORE_INCREMENT` |
| 3人同点で合計が100,000点に満たない | `30,000 / 30,000 / 30,000 / 9,000` | `INVALID_SCORE_TOTAL` |

表の全項目が自動テストで期待どおりになり、成績を返せない場合は該当する理由を取得できることを確認する。
