# 半荘の素点入力と成績表示の仕様・設計・テスト項目

## 仕様

卓で供託を精算したあとの素点を入力し、４人が同じ端末で名前、素点、着順、成績ポイントを確認する。入力と確認はAndroidとiOSで共通の１画面に置く。選手の登録、その日の表示順の設定、席の入力、端末への半荘の保存、リーグ順位への反映は後続の作業で扱う。[手順書0005](../procedures/0005-enter-match-scores.md)

### 素点を入力する

「選手A」「選手B」「選手C」「選手D」をこの順で表示する。各選手の「素点（点）」欄は空欄で始める。半角数字と、先頭に１つだけ置ける半角の `-` を受け付ける。編集途中の空欄と `-` 単体も許す。入力や貼り付けでこの条件を外れる場合は、操作全体を取り消して直前の値を保つ。例えば `35000` と `-1100` は入力でき、`35,000`、`３５０００`、`35.0` は受け付けない。画面に点単位の入力例を示し、両OSでソフトウェアキーボードから負の素点を入力できるようにする。

### 成績を確認する

「成績を確認」を押すと４欄を検証する。空欄には入力を求め、`-` 単体や `Int` の範囲外には点単位の整数を求める。該当する欄が複数あればすべてに表示する。４欄とも整数に変換できた場合はMリーグ方式の順位点で計算する。計算できないときは、次の理由のうち計算から返った１つを画面に表示する。[半荘成績の計算仕様](match-results.md#入力エラーと対象外の半荘)

| 計算が返す理由 | 画面の文言案 |
| --- | --- |
| `INVALID_SCORE_INCREMENT` | 素点は100点刻みで入力してください。 |
| `INVALID_SCORE_TOTAL` | ４人の素点の合計を100,000点にしてください。 |
| `UNSUPPORTED_TIE` | ３人以上が同点の半荘は紙に記録してください。 |

今回のルールでは４人の素点の合計を100,000点に固定する。

計算に成功したら、同じ画面に４人分の名前、素点、着順、成績ポイントを入力欄と同じ順で表示する。素点は `35,000` や `-1,100` のように桁を区切る。成績ポイントは小数１桁とし、正数に `+`、負数に `-` を付け、ゼロは `0.0 pt` と表示する。エラーは文言でも伝える。

入力欄の値が変わった直後に、表示中の成績と計算エラーを消す。編集した欄のエラーも消し、ほかの欄のエラーは残す。値を元に戻しても、改めて「成績を確認」を押すまでは消した成績やエラーを表示しない。ボタンを押すとその時点の４欄を検証して計算する。拒否された貼り付けやカーソル移動など、入力欄の値を変えない操作では表示を保つ。

入力欄で元に戻す・やり直す操作が使える場合は、直近の「成績を確認」以降の編集に適用する。

画面を回転しても、入力値と表示中の結果・エラーを保つ。アプリを終了して新しく起動した場合は、４欄とも空欄から始める。

## 設計

`shared/src/commonMain` の `App()` から共通の入力画面を表示する。入力欄はMaterial 3の `OutlinedTextField` に `TextFieldState` を渡す。キーボードに隠れる欄やボタン、縦の表示領域が狭いときの結果にはスクロールで到達できるようにする。既存の `MaterialTheme` を使い、画面で個別に色が必要な場合は `MaterialTheme.colorScheme` の役割に合った色を参照する。

`InputTransformation` で編集後の文字列全体が `-?[0-9]*` に当てはまるかを判定する。形式から外れる編集は `revertAllChanges()` で取り消す。同じ文字列への置き換えも編集履歴に残さないよう、文字の変更を `revertAllChanges()` で取り消してから、置き換え後の選択範囲を反映する。`KeyboardOptions` では `KeyboardType.NumberSigned` を指定する。Compose Multiplatform 1.12.2のiOS標準のテキスト入力ではこの指定が通常のキーボードにフォールバックするため、マイナスを入力できることを両OSで確かめる。[Composeの入力変換](https://developer.android.com/develop/ui/compose/text/user-input#filter-user-input-with-input-transformations)

入力形式の判定と、確認時の変換・計算・表示用データの作成は共通Kotlinで行う。確認時は４欄の文字列を固定順に読み取り、空欄を判別したうえで `toIntOrNull()` を使う。４件とも変換できたら `RawScores` と `PlacementPoints(50, 10, -10, -30)` を `calculateMatchResults` に渡す。成功時は同じ位置の名前、素点、`PlayerResult` を１行分のデータにまとめる。成績ポイントは `pointsInTenths` の整数演算で符号と小数１桁を組み立てる。失敗時は理由を画面の文言に対応付ける。[半荘成績の設計](match-results.md#設計)

合計の検証に使う定数 `EXPECTED_SCORE_TOTAL` は画面からも参照できるよう `internal` とする。`INVALID_SCORE_TOTAL` の文言にはこの定数を桁区切りで整形して差し込む。将来リーグごとに合計点を設定する場合は、計算に渡すルールの合計点を表示にも使う。

画面の状態には４欄の `TextFieldState` と、最後の確認で得た欄ごとのエラー、成績または計算エラーを持つ。「成績を確認」を押すたびに４欄を検証し、確認結果を更新するとともに各欄の `undoState.clearHistory()` を呼ぶ。

確認後に `undoState.canUndo` または `canRedo` が真になった欄は、文字列が編集された欄として扱う。その欄のエラーは表示対象から外し、１欄でも該当すれば成績と計算エラーを表示対象から外す。元に戻す操作のあともやり直しの履歴が残るため、現在の文字列が確認時と同じでも消した表示は戻らない。`undoState` の利用箇所で `ExperimentalFoundationApi` にオプトインする。回転時の画面再生成に備えて、編集履歴を含む入力欄の状態と最後の確認結果にはComposeの状態保存を使う。半荘の履歴を端末に書き込む処理は保存機能を作るときに扱う。[UndoStateのAPI](https://developer.android.com/reference/kotlin/androidx/compose/foundation/text/input/UndoState)

## テスト項目

### 共通テスト

テストは `shared/src/commonTest/kotlin` に置き、`./gradlew :shared:testAndroidHostTest` で実行する。既存の計算テストに加えて、入力形式の判定、入力から確認結果を作る処理、欄ごとの編集履歴の有無に応じた表示を確かめる。画面での操作に対応する入力文字列と編集履歴の有無をテストに渡す。表の４人分の値と結果は選手A、B、C、Dの順に示す。

| 項目 | 入力・操作 | 期待する結果 |
| --- | --- | --- |
| 編集できる文字 | `35000`、`-1100`、空欄、`-` を判定する。`35,000`、`３５０００`、`35.0`、`+35000`、`35-000`、`--1100` も判定する。 | 前者は編集でき、後者は編集を拒否する。 |
| 欄ごとのエラー | 空欄、`-`、`2147483648`、`10000` で確認する。 | Aに空欄のエラー、BとCに整数として扱えない旨を表示する。Dに欄のエラーは出ず、成績と計算エラーも表示しない。 |
| 同着なし、負の素点あり | `20100 / 50000 / -1100 / 31000` で確認する。 | 着順は `3 / 1 / 4 / 2`、ポイントは `-19.9 / +70.0 / -61.1 / +11.0 pt`。Cの素点は `-1,100` と表示する。 |
| 同点トップ | `35000 / 20000 / 35000 / 10000` で確認する。 | 着順は `1 / 3 / 1 / 4`、ポイントは `+35.0 / -20.0 / +35.0 / -50.0 pt`。 |
| ゼロの成績ポイント | `60000 / 20000 / 15000 / 5000` で確認する。 | Bは `0.0 pt` と表示する。 |
| 100点刻み | `350 / 50000 / 19650 / 30000` で確認する。 | 成績の代わりに100点刻みの理由を表示する。 |
| 合計 | `50000 / 30000 / 20000 / -1000` で確認する。 | 成績の代わりに合計のエラーを表示する。文言に含まれる合計点は、検証に使う定数を桁区切りにした100,000点とする。 |
| ３人同点 | `30000 / 30000 / 30000 / 10000` で確認する。 | 成績の代わりに３人以上同点の理由を表示する。 |
| エラーの消去 | AとBに欄のエラーがある状態でAを編集する。別に、計算エラーがある状態からいずれかの欄を編集する。 | 最初の操作でAのエラーだけが消える。次の操作で計算エラーが消える。 |
| 確認後の入力の扱い | 成績を表示した状態で、形式に合わない編集を試す。次に有効な編集で値を変え、確認ボタンを押さずに元の値に戻す。 | 最初の操作では入力値と成績が残る。次の操作では成績が消え、元の値に戻しても表示されない。 |
| 結果の消去と再計算 | 同着なしの結果を表示し、AとBの素点を入れ替える。 | Aを編集した直後に結果が消える。再確認後は着順が `1 / 3 / 4 / 2`、ポイントが `+70.0 / -19.9 / -61.1 / +11.0 pt` となり、選手の表示順は変わらない。 |

### 再コンポーズを挟まない編集の確認

各項目は同着なしの入力で成績を表示した状態から始める。Aの素点 `20100` の末尾にカーソルを置き、実際の入力欄に２件の編集を別々に送り、その間に再コンポーズを挟まない状態で確かめる。

| 操作 | 期待する結果 |
| --- | --- |
| `1` を挿入し、直後に削除する。 | 入力値は `201001`、`20100` の順に変わる。画面更新後の素点は `20100` で、成績は表示されない。 |
| `-` を挿入し、続けて `1` を挿入する。 | `-` は取り消され、`1` は入力できる。画面更新後の素点は `201001` で、成績は表示されない。 |

### AndroidとiOSでの画面確認

| 項目 | 確認方法と期待する結果 |
| --- | --- |
| 起動と入力 | 選手AからDが固定順で並び、４欄とも空欄で始まる。画面のキーボードで `-` に続けて `1100` を打てる。縦の表示領域が狭い状態でも、スクロールして４欄と「成績を確認」に到達できる。 |
| 貼り付け | 成績を表示してから既存の値を選択して `35,000` を貼り付け、元の値と成績が残ることを確かめる。同じ操作で `35000` が入ることを確かめる。 |
| 同じ文字列への置き換えと元に戻す操作 | `20100` を `20100` で置き換えても成績は残る。成績確認後に `1` を挿入し、入力欄で元に戻すと `20100` に戻り、成績は表示されない。 |
| 入力エラー | 空欄と `-` 単体を含む状態で確認し、それぞれの欄に理由が出る。次に全欄を整数にして合計を100,000点からずらし、画面に合計の理由が出る。 |
| 結果表示と再計算 | 共通テストの同着なしの入力で、４人の名前と桁区切りの素点、着順、ポイントを照合する。Aの素点を編集した直後、ボタンを押す前に結果が消える。Aを元の値に戻しても結果は表示されない。AとBを入れ替えた入力で確認すると、共通テストと同じ新しい結果が出る。 |
| 回転と再起動 | 入力途中、エラー表示中、成績表示中にそれぞれ画面を回転し、入力値と表示中の内容が残る。アプリを終了して新しく起動すると、４欄とも空欄で始まる。 |
| 元に戻す操作のあとの回転 | 成績を確認し、Aの素点 `20100` の末尾に `1` を挿入してから、入力欄の「元に戻す」操作で `20100` に戻す。「成績を確認」を押さずに画面を回転し、素点が `20100` のままで古い成績が表示されないことを確かめる。続けて「やり直す」操作で `201001` に戻ることを確かめる。 |
