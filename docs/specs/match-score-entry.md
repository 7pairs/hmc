# 半荘の素点入力と成績表示の仕様・設計・テスト項目

## 仕様

半荘ごとに各席に選手を割り当て、終局後に卓で供託を精算したあとの素点を入力する。4人が同じ端末で席、名前、素点、着順、成績ポイントを確認し、確認した半荘を端末に保存する。席の割り当て、素点入力、成績の確認と保存はAndroidとiOSで共通の1画面に置く。保存済みの半荘の見返しと訂正、リーグ順位への反映は後続の作業で扱う。（参照：[手順書0005](../procedures/0005-enter-match-scores.md)・[手順書0008](../procedures/0008-assign-players-to-seats.md)・[手順書0009](../procedures/0009-save-matches.md)）

### 席に選手を割り当てる

毎回東・南・西・北の順に各席の選手欄と「素点（点）」欄を表示する。選手欄はすべて未選択で始め、「選手を選ぶ」と表示する。各欄を開くと登録済みの全選手を候補に表示する。席はつかみ取りの直後に入力しておくことも、終局後に素点とまとめて入力することもできる。表示名の変更は選手登録画面で行う。（参照：[選手登録の仕様](initial-screen.md#選手を登録する)）

他の席に割り当てられた選手を選ぶと、2席の選手を入れ替える。例えば東がAさん、南がBさんのときに東でBさんを選ぶと、東がBさん、南がAさんになる。東が未選択の状態で南のBさんを東に選ぶと、東がBさん、南が未選択になる。どちらの場合も素点はそれぞれの席の欄に残す。

### 素点を入力する

各席の素点欄は空欄で始める。半角数字と、先頭に1つだけ置ける半角の `-` を受け付ける。編集途中の空欄と `-` 単体も許す。入力や貼り付けでこの条件を外れる場合は、操作全体を取り消して直前の値を保つ。例えば `35000` と `-1100` は入力でき、`35,000`、`３５０００`、`35.0` は受け付けない。画面に点単位の入力例を示し、両OSでソフトウェアキーボードから負の素点を入力できるようにする。

### 成績を確認する

選手が未選択でも「成績を確認」を押せる。押すと、4席すべてに選手が割り当てられ、選手IDが重複していないことを確かめる。未選択の欄には選択を求め、同じ選手が割り当てられている欄には重複を知らせる。

同時に各席の素点欄を検証し、空欄には入力を求め、`-` 単体や `Int` の範囲外には点単位の整数を求める。選手欄と素点欄のエラーは該当するすべての欄に表示する。両方の検証に通った場合はMリーグ方式の順位点で計算する。計算できないときは、次の理由のうち計算から返った1つを画面に表示する。（参照：[半荘成績の計算仕様](match-results.md#入力エラーと対象外の半荘)）

| 計算が返す理由 | 画面の文言案 |
| --- | --- |
| `INVALID_SCORE_INCREMENT` | 素点は100点刻みで入力してください。 |
| `INVALID_SCORE_TOTAL` | 4人の素点の合計を100,000点にしてください。 |
| `UNSUPPORTED_TIE` | 3人以上が同点の半荘は紙に記録してください。 |

今回のルールでは4人の素点の合計を100,000点に固定する。

計算に成功したら、同じ画面の入力欄の下に席、名前、素点、着順、成績ポイントを東・南・西・北の順で表示する。素点は `35,000` や `-1,100` のように桁を区切る。成績ポイントは小数1桁とし、正数に `+`、負数に `-` を付け、ゼロは `0.0 pt` と表示する。エラーは文言でも伝える。

選手の割り当てが変わった直後に、表示中の成績と、選手が変わった席の選手欄のエラーを消す。素点欄のエラーと計算エラーは残す。同じ選手を選び直したときは表示を保つ。

素点欄の値が変わった直後に、表示中の成績、計算エラー、編集した素点欄のエラーを消し、ほかの欄のエラーは残す。拒否された貼り付けやカーソル移動など、素点欄の値を変えない操作では表示を保つ。割り当てや素点を元に戻しても、改めて「成績を確認」を押すまでは消した成績やエラーを表示しない。

入力欄で元に戻す・やり直す操作が使える場合は、直近の「成績を確認」以降の編集に適用する。

### 半荘を保存する

成績の確認に成功し、その後に席の割り当てや素点を変更していない間は「この半荘を保存」を押せる。保存する半荘には確認に使った4人分の選手ID・席・素点を記録する。確認後に席の割り当てや素点を変えた場合は、再確認してから保存する。

保存中であることを表示する。保存の成否が決まるまで、席の割り当て、素点の編集、選手登録画面への移動、「成績を確認」と「この半荘を保存」の操作を受け付けない。保存に成功したら「保存しました」と伝え、次の半荘を開く。選手候補は登録済みの全選手を引き続き表示し、席と素点は空欄から始める。保存に失敗したらそのことを伝え、入力と確認結果を保って保存を再試行できるようにする。同じ入力中の半荘に対して保存操作を繰り返しても、記録は1件とする。

### 入力を再開する

画面を回転したときや、画面ロック・アプリ切り替えから戻ったときは、画面が再生成されても各席の選手と素点、表示中の成績やエラーを保つ。アプリを終了して新しく起動すると、登録済みの選手が4人以上なら素点入力画面を開く。登録済みの全選手を候補に表示し、4席とも選手未選択、素点空欄で始める。4人未満で起動した場合は選手登録画面を開く。（参照：[初期画面の仕様](initial-screen.md#仕様)）

## 設計

`shared/src/commonMain` の `App()` から共通の入力画面を表示する。入力欄はMaterial 3の `OutlinedTextField` に `TextFieldState` を渡す。キーボードに隠れる欄やボタン、縦の表示領域が狭いときの結果にはスクロールで到達できるようにする。既存の `MaterialTheme` を使い、画面で個別に色が必要な場合は `MaterialTheme.colorScheme` の役割に合った色を参照する。

共通画面は `imePadding()` でキーボードが占める領域を避ける。Androidではキーボードの領域を取得できるよう、Manifestの `MainActivity` に `android:windowSoftInputMode="adjustResize"` を指定する。（参照：[Androidのエッジツーエッジ設定](https://developer.android.com/develop/ui/compose/system/setup-e2e#configure-windowsoftinputmode)）

`InputTransformation` で編集後の文字列全体が `-?[0-9]*` に当てはまるかを判定する。形式から外れる編集は `revertAllChanges()` で取り消す。同じ文字列への置き換えも編集履歴に残さないよう、文字の変更を `revertAllChanges()` で取り消してから、置き換え後の選択範囲を反映する。`KeyboardOptions` では `KeyboardType.NumberSigned` を指定する。Compose Multiplatform 1.12.2のiOS標準のテキスト入力ではこの指定が通常のキーボードにフォールバックするため、マイナスを入力できることを両OSで確かめる。（参照：[Composeの入力変換](https://developer.android.com/develop/ui/compose/text/user-input#filter-user-input-with-input-transformations)）

選手の割り当てと素点欄の状態はそれぞれ席に対応付ける。割り当ては選手の識別子で保持し、画面に表示するときに名前を引く。入れ替えでは2席の割り当てをまとめて更新する。

選手の割り当ての更新と検証、入力形式の判定、確認時の変換・計算・表示用データの作成は共通Kotlinで行う。確認時は4席の選手と素点を東・南・西・北の順に読み取る。素点は空欄を判別したうえで `toIntOrNull()` を使う。選手と素点の検証に通ったら、既存の `calculateMatchResults` に `RawScores` と `PlacementPoints(50, 10, -10, -30)` を渡す。成功時は同じ席の名前、素点、`PlayerResult` を1行分のデータにまとめる。成績ポイントは `pointsInTenths` の整数演算で符号と小数1桁を組み立てる。失敗時は理由を画面の文言に対応付ける。（参照：[半荘成績の設計](match-results.md#設計)）

合計の検証に使う定数 `EXPECTED_SCORE_TOTAL` は画面からも参照できるよう `internal` とする。`INVALID_SCORE_TOTAL` の文言にはこの定数を桁区切りで整形して差し込む。将来リーグごとに合計点を設定する場合は、計算に渡すルールの合計点を表示にも使う。

画面の状態には選手の割り当て、各席の `TextFieldState`、最後の確認に使った入力、確認後に割り当てが変わった席の記録を持つ。確認時の入力から、選手欄と素点欄それぞれのエラー、成績または計算エラーを作る。「成績を確認」を押すたびに確認に使う入力を更新し、割り当てが変わった席の記録を消すとともに、各素点欄の `undoState.clearHistory()` を呼ぶ。

割り当てが変わった席は次の確認まで記録し、該当する選手欄のエラーと成績を表示対象から外す。入れ替えで両席が変わった場合は両席を記録する。現在の割り当てが確認時と同じ状態に戻っても記録を保つ。

確認後に `undoState.canUndo` または `canRedo` が真になった素点欄は、文字列が編集された欄として扱う。その素点欄のエラーは表示対象から外し、1欄でも該当すれば成績と計算エラーを表示対象から外す。元に戻す操作のあともやり直しの履歴が残るため、現在の文字列が確認時と同じでも消した表示は戻らない。`undoState` の利用箇所で `ExperimentalFoundationApi` にオプトインする。回転時の画面再生成に備え、選手の割り当て、割り当てが変わった席の記録、編集履歴を含む素点欄の状態、最後の確認に使った入力にはComposeの状態保存を使う。（参照：[UndoStateのAPI](https://developer.android.com/reference/kotlin/androidx/compose/foundation/text/input/UndoState)）

## テスト項目

### 共通テスト

テストは `shared/src/commonTest/kotlin` に置き、`./gradlew :shared:testAndroidHostTest` で実行する。既存の計算テストに加えて、選手の割り当て、入力形式の判定、確認結果の作成、編集後の表示を確かめる。表の4席分の値と結果は東・南・西・北の順に示す。割り当ての指定がなければAさん、Bさん、Cさん、Dさんの順とする。

| 項目 | 入力・操作 | 期待する結果 |
| --- | --- | --- |
| 編集できる文字 | `35000`、`-1100`、空欄、`-` を判定する。`35,000`、`３５０００`、`35.0`、`+35000`、`35-000`、`--1100` も判定する。 | 前者は編集でき、後者は編集を拒否する。 |
| 席の入れ替えと移動 | 東がAさん、南がBさんの状態で東にBさんを選ぶ。続けて未選択の西にBさんを選ぶ。 | 最初は東がBさん、南がAさんになる。次に西がBさん、東が未選択になる。両方の操作で素点は各席に残る。 |
| 選手と素点のエラー | 選手は東を未選択、南と西をBさん、北をDさんとし、素点は空欄、`-`、`2147483648`、`10000` で確認する。 | 東の選手欄に未選択、南と西の選手欄に重複のエラーを出す。東の素点欄に空欄、南と西の素点欄に整数として扱えない旨を表示する。北に欄のエラーは出ず、成績と計算エラーも表示しない。 |
| 選手欄の検証と成績計算の順序 | 東が未選択の状態で素点を `50000 / 30000 / 20000 / -1000` として確認する。 | 東の選手欄に未選択のエラーを出す。計算は行わず、合計のエラーは表示しない。 |
| 同着なし、負の素点あり | `20100 / 50000 / -1100 / 31000` で確認する。 | 席順にAさん、Bさん、Cさん、Dさんを表示する。着順は `3 / 1 / 4 / 2`、ポイントは `-19.9 / +70.0 / -61.1 / +11.0 pt`。西の素点は `-1,100` と表示する。 |
| 同点トップ | `35000 / 20000 / 35000 / 10000` で確認する。 | 着順は `1 / 3 / 1 / 4`、ポイントは `+35.0 / -20.0 / +35.0 / -50.0 pt`。 |
| ゼロの成績ポイント | `60000 / 20000 / 15000 / 5000` で確認する。 | 南は `0.0 pt` と表示する。 |
| 100点刻み | `350 / 50000 / 19650 / 30000` で確認する。 | 成績の代わりに100点刻みの理由を表示する。 |
| 合計 | `50000 / 30000 / 20000 / -1000` で確認する。 | 成績の代わりに合計のエラーを表示する。文言に含まれる合計点は、検証に使う定数を桁区切りにした100,000点とする。 |
| 3人同点 | `30000 / 30000 / 30000 / 10000` で確認する。 | 成績の代わりに3人以上同点の理由を表示する。 |
| 欄のエラーの消去 | 東と南の選手欄と素点欄にエラーがある状態で、東に未割り当ての選手を選ぶ。続けて南の素点を編集する。 | 最初は東の選手欄のエラーだけが消える。次に南の素点欄のエラーだけが消える。 |
| 選手の移動後のエラー | 東と西の選手を未選択、南をBさん、北をDさんとし、素点は `20100`、`50000`、空欄、`31000` で確認する。次に東でBさんを選び、改めて確認する。 | 最初は東と西の選手欄、西の素点欄にエラーを出す。Bさんを東に移すと東の選手欄のエラーだけが消える。西の選手欄と素点欄のエラーは残り、空いた南の選手欄には再確認したときに初めてエラーを出す。 |
| 計算エラーの消去 | 計算エラーがある状態で選手を入れ替え、続けていずれかの素点欄を編集する。 | 選手の入れ替え後も計算エラーは残り、素点を編集すると消える。 |
| 確認後の入力の扱い | 成績を表示した状態で、形式に合わない編集を試す。次に有効な編集で値を変え、確認ボタンを押さずに元の値に戻す。 | 最初の操作では入力値と成績が残る。次の操作では成績が消え、元の値に戻しても表示されない。 |
| 素点の編集と再計算 | 同着なしの結果を表示し、東と南の素点を入れ替える。 | 東を編集した直後に結果が消える。再確認後は着順が `1 / 3 / 4 / 2`、ポイントが `+70.0 / -19.9 / -61.1 / +11.0 pt` となり、選手の表示順は変わらない。 |
| 選手の選び直しと再確認 | 同着なしの結果を表示する。東でAさんを選び直す。次に東でBさんを選び、再確認する。再確認後に東でAさん、Bさんの順に選ぶ。 | Aさんの選び直しでは成績が残る。Bさんを選ぶと成績が消え、再確認すると東にBさん、南にAさんを表示する。各席の素点、着順、ポイントは同着なしの結果と同じ。割り当てを再確認時と同じ状態に戻しても成績は再表示されない。 |

### 再コンポーズを挟まない編集の確認

各項目は同着なしの入力で成績を表示した状態から始める。東の素点 `20100` の末尾にカーソルを置き、実際の入力欄に2件の編集を別々に送り、その間に再コンポーズを挟まない状態で確かめる。

| 操作 | 期待する結果 |
| --- | --- |
| `1` を挿入し、直後に削除する。 | 入力値は `201001`、`20100` の順に変わる。画面更新後の素点は `20100` で、成績は表示されない。 |
| `-` を挿入し、続けて `1` を挿入する。 | `-` は取り消され、`1` は入力できる。画面更新後の素点は `201001` で、成績は表示されない。 |
