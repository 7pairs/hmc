## 目的と対象

hmcのファイルに適用するOSSライセンスを選び、選定理由と適用範囲をリポジトリに記録する。対象はコード、文書、設定、画像など、hmcでライセンスを付与できるすべてのファイルとする。別ライセンスが明示されているSDDとSora Flow、およびリポジトリに取り込んだ第三者の著作物は対象外とする。

候補を比較するときは、再利用者がhmc由来の部分と元の公開先をたどれることを最優先とする。再配布時の著作権表示やライセンス表示の条件と、hmc側で出典を示す方法を確認する。広く再利用してもらえるよう、再配布時にソース公開を求めない候補を優先する。

## 手順

### 1. OSSライセンス候補を比較する

候補の出典、再配布時に必要な表示、ソース公開の条件、hmcで元の公開先を示す方法を比較表にまとめ、手順書の作業記録に残す。そらは比較表の記述を各ライセンスの本文と照合する。うみは比較が本文に沿っているか、合意した選定基準で判断できるだけの情報が揃っているかを確認する。二人で比較表とレビュー結果を読み、採用案に合意する。

### 2. 選定理由と適用範囲をADRに記録する

現時点のリポジトリのファイルと既存のライセンス表示を確認する。`docs/adr/0001-select-oss-license.md`に候補、採用理由、他の候補を見送った理由、現在のファイルのうち採用したライセンスが適用される範囲と対象外を記録する。そらはADRを比較表、二人の合意、既存のライセンス表示と照合する。

採用する候補の表示条件に基づき、追加・更新するファイルと表示方法を決め、手順書の作業記録に残す。想定する再利用の形と、その場合に再配布物に残る表示も同じ箇所に記録する。うみはADRが比較結果と合意を反映しているか、反映方法が採用したライセンスの条件を満たすか、想定した再利用の形で元の公開先をたどれるかを確認する。二人でADR、反映方法、検証に使う再利用の形に合意し、オーナーの着手依頼を受けてから手順3に進む。

### 3. 採用したライセンスをリポジトリに反映する

合意した場所にライセンス本文と必要な表示を追加し、元の公開先と適用範囲を確認できるようにする。そらは差分を確認し、追加・更新したファイルと表示が合意どおりか、ライセンス本文が出典と一致するか、対象外のファイルと既存の表示に意図しない変更がないかを確かめる。うみも同じ観点で反映結果を独立にレビューする。二人で差分とレビュー結果を確認し、検証に進むことに合意する。

### 4. ライセンスの反映結果を検証する

リポジトリを初めて読む人がライセンス本文と元の公開先を見つけ、採用したライセンスの適用範囲と対象外を判断できることを確かめる。手順2で合意した再利用の形に沿って再配布物の例を用意し、そこに残る表示から受け取った人がhmc由来の部分を識別し、元の公開先へたどれることを確かめる。参照先のリンクを確認し、コード構造の見直し対象がないことを差分で確かめる。結果を手順書に記録し、うみは検証結果が完了条件を満たすかを確認する。

## 作業記録

各手順の実施結果、検証・レビューの結果または参照先、予定から変わった点と理由、残った課題を記録する。うみの指摘は要点、採否と理由、再レビュー結果を残す。

## 完了条件

二人で選定理由をADRで確認し、採用したライセンスと適用範囲がADRとリポジトリの表示で一致していることを確かめる。想定した再配布物からhmc由来の部分と元の公開先を確認でき、手順4の検証と必要なレビューが完了していることも確かめる。オーナーが何にどのライセンスが適用されるか、なぜ選んだかを自分の言葉で説明できたら作業を完了とする。
