# 0001 ライセンスにApache License, Version 2.0を採用する

- **ステータス** 採用

## 背景

hmcはオープンソースで開発する。ライセンスの選定では、再配布物を受け取った人がhmc由来の部分を識別し、元の公開先へたどれることを優先した。広く再利用してもらえるよう、再配布時にソースの提供を求めないライセンスを検討した。

## 決定と適用範囲

hmcでライセンスを付与できるファイルにはApache-2.0を適用する。現在のリポジトリでは、プロジェクト憲章、開発プロセス、手順書、リポジトリの設定などが対象となる。

`docs/sdd/` と `docs/sora-flow/` は適用対象外とする。両ディレクトリの文書にはCC BY 4.0が適用され、画像には既存の説明に記載した許諾範囲でCC BY 4.0が適用される。現時点で適用対象外となるのは、この2ディレクトリである。今後取り込む第三者の著作物も適用対象外とし、その著作物に適用される条件に従う。（参照：[SDDのライセンスと出典](../sdd/README.md)・[Sora Flowのライセンス](../sora-flow/README.md)）

## 採用理由

Apache-2.0は再配布時にソースの提供を求めない。派生物をソース形式で配布する場合は、第4条(c)により、元のソースにある出典表示のうちその派生物に関係するものを残す。元の配布物に `NOTICE` を含めた場合、第4条(d)により、派生物をソース形式または生成物として配布する際に、その派生物に関係する出典表示を読める形で引き継ぐ。hmcの名前、由来箇所、元の公開先をその表示に含めれば、生成物を受け取った人にも出典を伝えられる。（参照：[Apache-2.0第4条](https://www.apache.org/licenses/LICENSE-2.0)）

## 見送った候補

- MITとBSD-3-Clauseも、再配布時にソースの提供を求めない。著作権表示は引き継がれるが、そこに含めず別に記載した公開先のURLや由来箇所の説明を引き継ぐ条件は本文に明記されていない。出典を引き継ぐ仕組みを優先してApache-2.0を選んだ。
- GPL-3.0は対象となる著作物をオブジェクトコードで配布する場合に対応するソースの提供を求めるため、見送った。

各候補の比較と再利用例は手順書に記録した。ライセンス本文と出典表示を置く場所や適用範囲の示し方も手順書で定め、想定した再配布物からhmc由来の部分と元の公開先をたどれるかを確かめる。（参照：[OSSライセンス選定の手順書](../procedures/0001-select-oss-license.md)）
